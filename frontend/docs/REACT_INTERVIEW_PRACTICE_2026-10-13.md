#### 对照解析（2026-10-13 20:45）

原回答抓住了“函数组件本质上是 JavaScript 函数，可以组织界面逻辑与展示”这个起点。需要修正以下三个概念。

1. **JSX 与 HTML：** 函数组件中可以使用 JSX 描述界面。JSX 是 JavaScript 的语法扩展，需要编译；它看起来像 HTML，但不是 HTML。当前项目中的 `View`、`Text` 是 React Native 组件。组件返回的 React 元素描述希望展示什么，并不是已经显示出来的界面。JSX 也不是函数组件专属的语法。
2. **导入与渲染：** `import` 只是把其他模块导出的函数引入当前文件，不会自动执行组件函数或获取它的返回值。在 JSX 中使用组件，才是在界面描述里告诉 React 这里需要这个组件，并传入相应的 props。React 在渲染时调用组件函数，根据返回结果组织界面，再由对应平台的渲染器更新实际界面。
3. **JSX 使用与直接调用：** `<ContextPrompt ... />` 让 React 识别一个组件边界，管理它在组件树中的身份、状态和渲染。`ContextPrompt(...)` 是立即执行普通函数调用，不会为它建立独立的组件边界。简单情况下画面可能相似，但语义不等价。尤其组件使用 Hooks 时，在父组件渲染期间直接调用会让这些 Hook 调用归入当前正在渲染的父组件；如果再放进条件或循环中，容易破坏 Hook 调用规则。组件应通过 JSX 使用，让 React 调用。

```text
导入组件函数
  → 在 JSX 中声明使用组件并传入 props
  → React 在渲染时调用组件函数
  → 组件返回界面描述
  → 渲染器把需要的变化应用到实际界面
```

**可以用于面试的回答：**

> 函数组件本质上是 JavaScript 函数，通常接收 props，并结合自身状态返回描述界面的 JSX。JSX 会被编译为创建 React 元素的代码，不是直接写入界面的 HTML。React 负责在渲染时调用组件，并根据返回结果更新界面。`import` 只负责导入组件函数。通过 JSX 使用组件和直接调用函数不等价：前者让 React 管理组件的身份、状态及渲染，后者只是一次普通函数调用，因此组件应通过 JSX 使用。

#### 讨论追问一：两个输入卡片是否共享状态？

**问题：** 如果首页同时放两个 `<ContextPrompt />`，在第一个输入框里输入文字，第二个会跟着变化吗？输入内容由谁保存？这里省略了实际使用时必传的 `onSubmit` 属性。

**我的原始回答：**

> 会，都保存？

**正确答案：**

不会跟着变化。当前组件内部使用 `const [prompt, setPrompt] = useState('')`，React 会为组件树中两个独立位置的 `ContextPrompt` 分别维护状态。第一个输入框调用与自身关联的 `setPrompt`，只更新自己的输入状态。

```text
第一个 ContextPrompt → prompt：'水果早餐'
第二个 ContextPrompt → prompt：''
```

状态由 React 保存，并关联到组件在树中的身份，而不是保存在组件函数上的一份共享变量。组件通过 `useState` 读取和更新自己的状态。“使用同一个组件函数”不等于“共用一份状态”。原回答中的“都保存”，如果指各自保存一份，是正确方向。

#### 讨论追问二：如何让两个输入框保持同步？

**问题：** 如果产品要求两个输入框始终显示同样的文字，把 `prompt` 放在它们共同的父组件里，会不会更方便？为什么？

**我的回答：** 尚未作答，保留此处供后续补充。

**参考答案：**

会。可以把 `prompt` 状态提升到共同父组件，再通过 props 把同一个值和更新回调传给两个输入卡片。输入卡片使用传入的值展示内容，通过回调请求父组件更新状态，不再各自维护一份输入状态。任意一个输入框发生变化，父组件更新这份状态，两个输入框都会收到新的值，因此保持同步。

这使两个输入框共享一个数据来源，避免维护两份状态并额外处理相互同步。对于这个局部需求，共同父组件的 state 和 props 就足够。

**本题复习重点：** JSX 描述界面；import 导入函数；React 管理组件身份和状态；同一组件的不同实例默认不共享内部 state；需要同步时可以提升状态。

- [React 调用组件与 Hooks](https://react.dev/reference/rules/react-calls-components-and-hooks)
